# Ideas from the night of 2026-11-16

Niche: AI / developer tools. Builder: solo developer, $500 to $5,000, 15 to 30 hours a week.

## Honest headline

Eight pain themes cleared a first read. Five scored 18+ out of 25. After the competitor search, **only two ideas survived, and only one cleanly**. The third slot is filled by the best idea that did not clear the bar, marked as such. I would rather hand you one tested idea than three exciting ones.

All quotes are from Hacker News comments or GitHub issues posted between 2026-10-18 and 2026-11-17. Reddit, X and G2 were not readable from this environment, so nothing is quoted from them.

## 1. Killcount (working name) — 19/25

**Pitch:** A pull-request check that plants small bugs in the lines an agent just changed and tells you in minutes which ones the new tests failed to catch.

**Gap it fills:** Agents now write the code and the tests. Green tests prove little when the same model wrote both. Mutation testing answers "would these tests catch a bug?", but today it is a slow, whole-repo, do-it-yourself job with no PR feedback.

**Who has the pain:** Tech lead or senior engineer on a 5 to 50 developer product team where Claude Code, Codex or Cursor writes most PRs. The moment: approving a PR whose tests are green and which nobody has read line by line.

**Proof:**

1. "The part that makes me uneasy is when the AI writes both the code and the tests. They might agree with each other and still miss the same thing. How are people here checking for that without doing the whole job twice?" — edwin0, 2026-10-19, [HN](https://news.ycombinator.com/item?id=50151648) (8 replies)
2. "Some people think that as long as it passes all tests, that's all jolly - but it still needs a code review to check whether all the tests are still relevant and whether everything that needs to be tested is tested." — muzani, 2026-10-30, [HN](https://news.ycombinator.com/item?id=50299185)
3. "Even with such a strict environment, I am ending up with problems, and of course, when asking Claude, the answer is "This is on me; I did not do X and Y"" — abalgir, 2026-10-23, [HN](https://news.ycombinator.com/item?id=50209084)

Supporting signal: at least four other commenters describe running mutation testing by hand to police agent tests ([drooby](https://news.ycombinator.com/item?id=50439296), [webarchitect](https://news.ycombinator.com/item?id=50154869), [mcv](https://news.ycombinator.com/item?id=50446064), [daniiel](https://news.ycombinator.com/item?id=50345227)). A July 2026 industry digest lists half a dozen new hobby tools for the same job ([mutating.tech](https://mutating.tech/blog/the-mutation-testing-digest-for-july-2026/)).

**Score:** frequency 4, intensity 4, willingness to pay 3, reachability 4, buildability 4.

**Closest competitors and why they miss:**

| Competitor | What it does | Why it misses |
|---|---|---|
| Stryker, mutmut, PIT | Open-source mutation runners | Whole-repo by default, slow, no PR comment. The cashu-ts project added a Stryker PR gate and removed it over 10 to 90 minute runs, inherited survivors and no bot feedback, per the digest above |
| CodeRabbit ($24 to $90/user/mo) | AI review; generates unit tests on higher tiers | Its pricing page lists test generation, not test quality measurement |
| AITG, MTT Harness, Crucible | Hobby repos that scope mutation to changed code | Unfunded, single-language, no hosted product |
| The Mutating Company | Says it builds verification for coding agents | Site lists no such product or price; contact-only |
| Meta's just-in-time testing | Mutation-guided tests at PR time | Internal to Meta |

I found no funded, hosted product that does diff-only mutation with PR feedback. I did not find Arcmutate or Stryker Dashboard pricing; check them before building.

**Pricing guess (estimate):** Free for public repos. $99 a month per team of up to 10 developers. Reasoning: it must sit below CodeRabbit's $24 to $30 per seat, and a flat team price avoids a per-seat argument for a single check.

**MVP:**

- **Core feature:** GitHub Action. Mutate only the lines changed in the PR, run only the tests that cover them, stop at a 5-minute budget, post one PR comment listing each surviving change ("`>=` became `>` on line 42 and no test failed").
- **Agent loop:** emit survivors as JSON plus a ready prompt, so the coding agent can write the missing tests before a human looks.
- **Skip:** dashboard, mutation score history, more than two languages, your own mutation engine, billing.
- **Stack:** TypeScript Action wrapping StrykerJS for TypeScript; mutmut for Python. GitHub App and Postgres only once someone asks for the hosted version.

**14-day plan:**

| Days | Work |
|---|---|
| 1 to 2 | Run Stryker by hand on changed lines of 5 public agent-written PRs. Record run time and survivors. This is also the risk test below |
| 3 to 6 | TypeScript Action: diff parsing, line-scoped mutation, covering-test selection, time budget |
| 7 to 8 | PR comment with only new survivors; JSON output and agent prompt |
| 9 to 11 | Python support through mutmut |
| 12 | Docs and a 60-second demo on a real PR |
| 13 to 14 | Install with 3 design partners; fix what breaks |

**First 10 customers:**

- The seven commenters linked above. Reply in the thread or use the contact in their profile.
- Maintainers of AITG, MTT Harness and Crucible, as design partners rather than customers.
- The cashu-ts maintainers, whose reasons for removing their gate are your spec.
- Stryker and mutmut community channels.

Message: "You said you check agent-written tests with mutation testing by hand. I built a PR check that does only the changed lines in under 5 minutes and comments with the survivors. Can I run it on one of your PRs and send you the result? No install needed."

**Biggest risk:** Teams will not pay for a check the agent can run itself from a prompt. drooby already does this with seven manual steps.

**Cheapest test this week:** Do days 1 to 2 only. If the survivors on 5 real agent-written PRs are not obviously alarming, stop. If they are, send the reports to 10 teams and count how many ask to install it. Three or more is a go.

### WHAT WOULD KILL THIS IDEA?

- CodeRabbit, Copilot or Claude Code ships "test strength" on PRs. Plausible within months; it is a natural feature for all three.
- Diff-only runs still take over 10 minutes on real repos, which repeats the cashu-ts failure.
- Survivors are mostly noise (equivalent mutants), so developers mute the comment.
- "Plenty of solutions" is the common view. One commenter said exactly that ([klaussilveira](https://news.ycombinator.com/item?id=50452776)). If buyers agree, there is no sale.
- Could a big company copy it in a weekend? The Action, yes. Low noise and fast runs across real repos take longer.

## 2. Clientwall (working name) — 18/25, weak gap

**Pitch:** A per-client context vault for developers who serve several clients: each client's decisions, tickets and rules in a walled store that any coding agent reads through MCP.

**Gap it fills:** Agent memory is per tool and per folder. Consultants re-explain decisions every session and fear one client's context reaching another's. The "how" is solved by skills; the "what happened" is not.

**Who has the pain:** Freelance developer or 2 to 10 person agency with 3 or more active clients, using Claude Code and Codex together. The moment: opening a session for client B on Monday and re-typing what was decided on Friday's call.

**Proof:**

1. "The major time cost for me is to re-explaining context and past decisions, client rules, that we already do." — Michel_Aventin, 2026-11-07, [Ask HN](https://news.ycombinator.com/item?id=50403153) (102 points, 71 comments)
2. "What breaks for me is the "what happened". a decision taken in a meeting, a new comment in a ticket." — Michel_Aventin, 2026-11-14, [HN](https://news.ycombinator.com/item?id=50500805)
3. "I keep a separate knowledge base per client and let the agent retrieve from that, instead of pasting everything into the prompt. Much less re-explaining, and no mixing up clients" — JustRouzbeh, 2026-11-09, [HN](https://news.ycombinator.com/item?id=50433055)

Supporting signal: at least ten people in that thread describe a tool they built themselves for this.

**Score:** frequency 5, intensity 3, willingness to pay 2, reachability 4, buildability 4.

**Closest competitors and why they miss:**

| Competitor | What it does | Why it misses |
|---|---|---|
| Estratos | Per-client knowledge base with enforced isolation | Aimed at accounting, law and marketing firms; invite-only; not built for coding agents |
| Farero | Free desktop app, many agents, searchable chat history | Organised by repo, not by client; no ingestion of tickets or meeting notes |
| CLAUDE.md, AGENTS.md, built-in memory | Per-folder instructions and memory | Per tool; no cross-agent store; no isolation guarantee |
| Home-made markdown and wiki setups | What most of the thread uses | Agents do not reliably write decisions down ([spockz](https://news.ycombinator.com/item?id=50422279)) |

I did not check funded memory APIs (mem0, Zep, Letta) tonight. They target app builders, but verify before building.

**Pricing guess (estimate):** $19 a month solo, $15 per seat for agencies. Reasoning: it has to cost less than one coding subscription, and the buyer bills clients by the hour.

**MVP:**

- **Core feature:** local daemon plus MCP server. One SQLite file per client. `cw use client-b` mounts only that client's store, so the agent cannot see the others.
- **Ingest:** GitHub, Linear or Jira comments, and a drop folder for meeting notes. Every stored decision keeps its source link.
- **Skip:** email, knowledge graphs, team sync, cloud hosting.
- **Stack:** TypeScript or Go daemon, SQLite with full-text search, MCP server.

**14-day plan:** days 1 to 3 store and MCP server; 4 to 6 ticket ingestion; 7 to 8 notes folder and decision extraction; 9 to 10 client switching and isolation tests; 11 to 12 installer and docs; 13 to 14 hand-hold 3 freelancers through setup.

**First 10 customers:** the self-builders in the [Ask HN thread](https://news.ycombinator.com/item?id=50403153), the monthly "Freelancer? Seeking freelancer?" thread, and small agencies. Message: "You said you keep a separate knowledge base per client. I'm building one that also pulls in ticket comments and meeting notes, and walls clients off from each other. Would you try it on one client for a week?"

**Biggest risk:** Everyone builds their own for free, so nobody pays.

**Cheapest test this week:** Ask 10 of the self-builders one question: "Would you pay $20 a month to stop maintaining yours?" Fewer than 3 yeses means stop.

### WHAT WOULD KILL THIS IDEA?

- The thread's author says "I'm exploring whether to build something". A direct competitor may already be under way.
- Anthropic or OpenAI ships cross-project memory with client scopes. This is a likely feature, and it would end the product.
- Is it really unknown? No. It is known and unsolved at a price people accept, which is a weaker claim.
- Would a stranger pay in week one? Unproven. The thread shows building, not buying.
- Could a big company copy it in a weekend? The store, yes. The ingestion connectors take longer but are not a moat.

## 3. Skill drift checker — 15/25, below the bar

**Do not build this yet.** It is here because it is the best of the rest, and the prompt asked for three.

**Pitch:** Re-run your agent skills against each new model release and flag the ones that changed behaviour.

**Who has the pain:** Developers who maintain their own skills for Claude Code or Codex, in the week after a model release.

**Proof:**

1. "This has bitten me so badly SO many times. Every time there's a new model, it's time to re-evaluate the skills." — codedrift_, 2026-11-10, [HN](https://news.ycombinator.com/item?id=50445763)
2. "This is harder and more annoying (because creating benchmarks is hard)" — bisonbear, 2026-11-09, [HN](https://news.ycombinator.com/item?id=50427183)
3. "Doing something like that currently for processing PDFs and it's a bit cumbersome" — barrenko, 2026-11-09, [HN](https://news.ycombinator.com/item?id=50427500)

**Score:** frequency 2, intensity 3, willingness to pay 2, reachability 3, buildability 5.

**Closest competitors:** skilljack-evals, skill-eval and agent-skills-eval (open source), promptfoo's skills guide, and the vendors' own skill evals. They compare skill versions; holding the skill fixed and varying the model is a configuration change away.

**Pricing guess (estimate):** none worth making. I found no sign anyone pays for this.

**MVP, if the signal grows:** a CLI that takes 3 prompts per skill, runs them on the old and new model, and diffs pass rate and cost.

**Cheapest test:** none this week. Watch whether the theme returns after the next model release.

### WHAT WOULD KILL THIS IDEA?

It is nearly dead already: three people in one small thread, free tools exist, and vendors ship their own evals.
